## 架构改进

### 之前的架构

```
UI 模块 → RWDb::writeAuditTrailLog() → 直接操作数据库
```

**问题**：
- 每个模块都需要直接操作数据库
- 数据库连接管理分散
- 难以统一管理和维护

### 现在的架构

```
UI 模块 → LOG_IF.writeAuditTrailLog() → LogModule → RWDb → 数据库
```

**优势**：
- ✅ 统一的日志接口
- ✅ 自动数据库连接管理
- ✅ 集中的日志逻辑
- ✅ 易于维护和扩展
- ✅ 线程安全

## CoreLog 模块改进

### 1. 数据库连接管理

```cpp
class LogModule::Impl {
public:
    std::unique_ptr<HGMACHINE::HGLogService> m_logService;
    std::string m_dbPath;
    bool m_dbInitialized;
    
    void ensureDatabaseOpen() {
        if (!m_dbInitialized && !m_dbPath.empty()) {
            RWDb::openDB(m_dbPath);
            m_dbInitialized = true;
        }
    }
};
```

### 2. 自动打开数据库

所有数据库操作前都会调用 `ensureDatabaseOpen()`：
- `getAuditTrailLogs()` - 读取日志前打开数据库
- `searchLogs()` - 搜索日志前打开数据库
- `getLogCount()` - 获取日志数量前打开数据库
- `getSearchLogCount()` - 获取搜索结果数量前打开数据库
- `getLogTableNames()` - 获取日志表名前打开数据库
- `writeAuditTrailLog()` - 写入日志前打开数据库

### 3. 数据库管理器单例

```cpp
std::shared_ptr<IDatabaseManager> SvcFactory::CreateDatabaseManager() {
    static std::shared_ptr<IDatabaseManager> instance = std::make_shared<DatabaseManagerAdapter>();
    return instance;
}
```

**效果**：整个应用只创建一个数据库连接实例，所有模块共享同一个连接。

## 使用示例

### 写入审计追踪日志

```cpp
#include "loginterface.h"

// 在任何 UI 模块中
LOG_IF.writeAuditTrailLog("用户登录成功");
LOG_IF.writeAuditTrailLog("修改系统配置");
LOG_IF.writeAuditTrailLog("导出数据");
```

### 读取审计追踪日志

```cpp
#include "loginterface.h"

// 读取日志
auto logs = LOG_IF.getAuditTrailLogs("AuditTrailLog_20250126");

// 搜索日志
int totalCount = 0;
auto results = LOG_IF.searchLogs("登录", "2025-01-26 00:00:00", "2025-01-26 23:59:59", 1, 10, &totalCount);
```
