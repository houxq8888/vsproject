# 审计追踪日志使用指南

## 概述

审计追踪日志功能已经迁移到 CoreLog 模块中，所有 UI 模块都可以通过 `LogInterface` 统一写入和读取审计追踪日志。

## 架构设计

### 1. CoreLog 模块 (modules/CoreLog)

CoreLog 模块负责审计追踪日志的读写操作，包括：

- **写入审计追踪日志**：`writeAuditTrailLog(const std::string& logContent)`
- **读取审计追踪日志**：`getAuditTrailLogs(const std::string& tableName)`
- **搜索审计追踪日志**：`searchLogs(...)`
- **获取日志数量**：`getLogCount(...)`, `getSearchLogCount(...)`
- **获取日志表名**：`getLogTableNames()`
- **导出日志**：`saveLogsToFile(...)`

### 2. LogInterface 接口 (interfaces/IfLog)

`LogInterface` 提供了单例模式的全局访问接口，所有 UI 模块都可以通过 `LOG_IF` 宏访问：

```cpp
#include "loginterface.h"

// 写入审计追踪日志
LOG_IF.writeAuditTrailLog("用户登录成功");

// 读取审计追踪日志
auto logs = LOG_IF.getAuditTrailLogs("AuditTrailLog_20250126");

// 搜索审计追踪日志
int totalCount = 0;
auto results = LOG_IF.searchLogs("登录", "2025-01-26 00:00:00", "2025-01-26 23:59:59", 1, 10, &totalCount);
```

### 3. 数据库管理

CoreLog 模块使用 `RWDb` 进行数据库操作，并实现了以下机制：

- **自动打开数据库**：在读写操作前自动打开数据库连接
- **单例模式**：使用 `SvcFactory::CreateDatabaseManager()` 创建单例数据库管理器
- **引用计数**：避免数据库被多次打开和关闭

## 使用示例

### 示例 1：在登录模块中写入审计追踪日志

```cpp
#include "loginterface.h"

void HGLoginWidget::onLoginClicked() {
    std::string userName = m_userNameCombo->currentText().toStdString();
    
    // 写入登录尝试日志
    LOG_IF.writeAuditTrailLog("用户 " + userName + " 尝试登录");
    
    if (checkPassword(userName, password)) {
        // 登录成功
        LOG_IF.writeAuditTrailLog("用户 " + userName + " 登录成功");
    } else {
        // 登录失败
        LOG_IF.writeAuditTrailLog("用户 " + userName + " 登录失败，密码错误");
    }
}
```

### 示例 2：在日志查看模块中读取审计追踪日志

```cpp
#include "loginterface.h"

void HGLogWidget::loadAuditTrailLogs() {
    // 获取所有审计追踪日志表
    auto tableNames = LOG_IF.getLogTableNames();
    
    // 读取最新的日志表
    if (!tableNames.empty()) {
        std::string latestTable = tableNames.back();
        auto logs = LOG_IF.getAuditTrailLogs(latestTable);
        
        // 显示日志
        for (const auto& log : logs) {
            std::string operatorName = log.at("Operator");
            std::string time = log.at("Time");
            std::string content = log.at("LogContent");
            
            // 在界面上显示
            displayLog(operatorName, time, content);
        }
    }
}
```

### 示例 3：搜索审计追踪日志

```cpp
#include "loginterface.h"

void HGLogWidget::searchLogs(const std::string& keyword, 
                            const std::string& timeFrom, 
                            const std::string& timeTo) {
    int totalCount = 0;
    int page = 1;
    int pageSize = 20;
    
    auto results = LOG_IF.searchLogs(keyword, timeFrom, timeTo, page, pageSize, &totalCount);
    
    // 显示搜索结果
    for (const auto& log : results) {
        displayLog(log);
    }
    
    // 显示总数
    displayTotalCount(totalCount);
}
```

### 示例 4：导出审计追踪日志

```cpp
#include "loginterface.h"

void HGLogWidget::exportLogs(const std::string& format) {
    auto logs = LOG_IF.getAuditTrailLogs("AuditTrailLog_20250126");
    std::string filePath = "audit_logs_20250126." + format;
    
    bool success = LOG_IF.saveLogsToFile(logs, filePath, format);
    
    if (success) {
        QMessageBox::information(this, "导出成功", "日志已成功导出到：" + QString::fromStdString(filePath));
    } else {
        QMessageBox::warning(this, "导出失败", "日志导出失败！");
    }
}
```

## 迁移指南

### 从 `RWDb::writeAuditTrailLog` 迁移到 `LOG_IF.writeAuditTrailLog`

**旧代码：**
```cpp
#include "rwDb.h"

RWDb::writeAuditTrailLog("用户登录成功");
```

**新代码：**
```cpp
#include "loginterface.h"

LOG_IF.writeAuditTrailLog("用户登录成功");
```

### 迁移步骤

1. **添加头文件**
   ```cpp
   #include "loginterface.h"
   ```

2. **替换函数调用**
   - 将 `RWDb::writeAuditTrailLog(...)` 替换为 `LOG_IF.writeAuditTrailLog(...)`
   - 将 `RWDb::readAuditTrailLog(...)` 替换为 `LOG_IF.getAuditTrailLogs(...)`

3. **移除数据库打开/关闭代码**
   - 不再需要手动调用 `RWDb::openDB()` 和 `RWDb::closeDB()`
   - CoreLog 模块会自动管理数据库连接

4. **测试**
   - 确保日志能够正确写入
   - 确保日志能够正确读取
   - 确保搜索功能正常工作

## 数据库表结构

审计追踪日志表结构如下：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| Time | TEXT | 时间戳 |
| Operator | TEXT | 操作员 |
| LogContent | TEXT | 日志内容 |

表命名规则：`AuditTrailLog_YYYYMMDD`

例如：`AuditTrailLog_20250126`

## 日志轮换策略

- 每个日志表最多存储 3000 条记录
- 当表中的记录数达到 3000 条时，自动创建新的日志表
- 新表名使用当前日期：`AuditTrailLog_YYYYMMDD`

## 注意事项

1. **不要直接使用 `RWDb`**：所有审计追踪日志操作都应该通过 `LogInterface` 进行
2. **数据库连接管理**：CoreLog 模块会自动管理数据库连接，不需要手动打开/关闭
3. **线程安全**：`LogInterface` 是线程安全的，可以在多线程环境中使用
4. **性能考虑**：大量写入日志时，建议使用批量写入或异步写入
5. **日志清理**：定期清理旧的日志表，避免数据库过大

## 总结

通过将审计追踪日志功能迁移到 CoreLog 模块，实现了以下目标：

1. **统一管理**：所有审计追踪日志操作都通过 CoreLog 模块进行
2. **简化使用**：UI 模块只需调用 `LOG_IF.writeAuditTrailLog()` 即可写入日志
3. **自动管理**：数据库连接自动管理，无需手动打开/关闭
4. **易于维护**：集中管理日志逻辑，便于后续维护和扩展
