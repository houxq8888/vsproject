# HG统一错误处理机制规范

## 概述

本文档定义了vsproject系统的统一错误处理机制，旨在提供一致、可追踪和可维护的错误处理方法。该错误处理机制包括错误码体系、异常处理框架、错误追踪和日志记录功能。

## 架构设计

### 核心组件

1. **HGError.h/cpp**: 定义错误码体系、异常类和错误信息类
2. **HGErrorHandler.h/cpp**: 实现标准错误处理器和错误处理基类
3. **HGErrorTracker.h/cpp**: 实现错误追踪和统计功能

### 设计原则

1. **统一性**: 所有模块使用相同的错误处理接口和错误码体系
2. **可追踪性**: 所有错误都能被追踪和记录，便于问题定位
3. **可扩展性**: 错误码体系和处理机制可以轻松扩展
4. **性能考虑**: 错误处理机制对系统性能影响最小

## 错误码体系

### 错误类别 (ErrorCategory)

错误类别按功能模块划分，每个类别有1000个错误码空间：

- **基础系统错误** (1000-1999): 系统初始化、资源、权限等
- **日志系统错误** (2000-2999): 日志初始化、写入、配置等
- **数据库错误** (3000-3999): 数据库连接、查询、事务等
- **网络通信错误** (4000-4999): 网络连接、协议、数据传输等
- **硬件设备错误** (5000-5999): 设备查找、连接、操作等
- **图像处理错误** (6000-6999): 图像格式、处理、分析等
- **用户界面错误** (7000-7999): UI初始化、资源、事件处理等
- **业务逻辑错误** (8000-8999): 业务操作、状态、验证等
- **第三方库错误** (9000-9999): 第三方库初始化、API、许可证等

### 错误严重级别 (ErrorSeverity)

- **INFO**: 信息级别，不影响系统正常运行
- **WARNING**: 警告级别，可能影响系统功能但不会导致系统崩溃
- **ERROR**: 错误级别，影响系统功能但可恢复
- **CRITICAL**: 严重错误级别，可能导致系统不稳定或崩溃

### 错误码分配规则

1. 每个模块的错误码从`模块_ERROR_BASE`开始，递增分配
2. 新增错误码需要在对应头文件中更新枚举
3. 错误码分配应记录在模块文档中

## 异常处理框架

### HGException类

HGException是所有异常的基类，包含以下信息：
- 错误类别 (ErrorCategory)
- 错误严重级别 (ErrorSeverity)
- 错误消息
- 唯一错误ID
- 错误追踪栈

### ErrorInfo类

ErrorInfo用于非异常情况下的错误传递，包含：
- 错误类别 (ErrorCategory)
- 错误严重级别 (ErrorSeverity)
- 错误消息

### 便捷宏定义

```cpp
// 抛出异常
HG_THROW_ERROR(code, message)
HG_THROW_CRITICAL(code, message)
HG_THROW_WARNING(code, message)

// 设置错误信息
HG_SET_ERROR(info, code, severity, message)

// 检查错误信息
HG_CHECK_ERROR(info)
```

## 错误处理基类

### ErrorHandlerBase类

所有需要错误处理的模块应继承ErrorHandlerBase类，该类提供：
- 统一的异常处理方法
- 错误信息处理方法
- 错误处理器访问接口

### 使用方式

```cpp
class MyModule : public ErrorHandlerBase {
public:
    void doSomething() {
        try {
            // 业务逻辑
            if (errorCondition) {
                HG_HANDLE_ERROR(ErrorCategory::BUSINESS_INVALID_OPERATION, 
                               ErrorSeverity::ERROR, 
                               "Invalid operation detected");
            }
        } catch (const HGException& ex) {
            // 异常已被基类自动处理，可以添加额外处理逻辑
        }
    }
};
```

## 错误追踪机制

### StandardErrorTracker类

StandardErrorTracker提供以下功能：
- 错误统计信息
- 最近错误记录
- 错误回调设置
- 追踪配置管理

### 错误统计信息

ErrorStatistics结构包含：
- 总错误数
- 各严重级别错误数
- 各类别错误数
- 错误发生时间范围

### 全局便捷函数

```cpp
// 追踪异常
trackException(ex);

// 追踪错误信息
trackErrorInfo(info);

// 获取错误统计
ErrorStatistics stats = getErrorStatistics();

// 获取最近错误
std::vector<HGException> recentErrors = getRecentErrors(10);

// 清除追踪记录
clearErrorTracking();

// 设置错误回调
setErrorTrackingCallback(callback);

// 启用/禁用自动追踪
enableAutoTracking(true);
disableAutoTracking();
```

## 错误处理规范

### 异常使用场景

1. **使用异常的情况**:
   - 系统无法继续执行的严重错误
   - 外部依赖不可用导致的错误
   - 数据完整性错误
   - 安全相关错误

2. **不使用异常的情况**:
   - 可预期的业务错误
   - 输入验证错误
   - 配置错误
   - 网络超时等可恢复错误

### 错误信息规范

1. **错误消息应包含**:
   - 错误描述（简洁明了）
   - 错误原因（如果已知）
   - 建议解决方案（如果适用）

2. **错误消息格式**:
   - 使用简单、明确的语言
   - 避免技术术语或提供解释
   - 保持一致性

3. **错误消息示例**:
   ```
   好的示例: "无法连接到数据库服务器，请检查网络连接和服务器状态"
   不好的示例: "DB connection failed"
   ```

### 错误处理流程

1. **检测错误**: 在业务逻辑中检测错误条件
2. **创建错误对象**: 使用适当的错误类别和严重级别
3. **记录错误**: 通过错误处理器记录错误
4. **处理错误**: 根据错误严重级别采取相应措施
5. **恢复/终止**: 尝试恢复或安全终止

## 日志记录规范

### 日志级别

- **INFO**: 一般信息，如系统状态、操作成功
- **WARNING**: 警告信息，如配置问题、性能问题
- **ERROR**: 错误信息，如操作失败、异常
- **CRITICAL**: 严重错误，如系统崩溃、数据丢失

### 日志内容

1. **时间戳**: 精确到毫秒
2. **错误ID**: 唯一标识符，便于追踪
3. **错误类别和严重级别**: 便于分类和过滤
4. **错误消息**: 详细的错误描述
5. **追踪栈**: 函数调用链和位置信息

### 日志文件

1. **常规日志**: 记录所有错误信息
2. **严重错误日志**: 专门记录CRITICAL级别错误
3. **日志轮转**: 按大小或时间轮转日志文件

## 性能考虑

1. **错误追踪**: 默认启用，可通过配置禁用
2. **日志记录**: 异步写入，避免阻塞主线程
3. **内存管理**: 限制追踪的错误数量，避免内存泄漏
4. **线程安全**: 所有错误处理操作都是线程安全的

## 最佳实践

1. **及时处理**: 错误应在发生时立即处理
2. **记录完整**: 记录足够的上下文信息便于调试
3. **避免吞没**: 不要捕获异常后不处理
4. **合理使用**: 区分可恢复错误和不可恢复错误
5. **测试覆盖**: 为错误处理逻辑编写测试用例

## 示例代码

### 基本错误处理

```cpp
#include "HGErrorHandler.h"

class DatabaseModule : public ErrorHandlerBase {
public:
    bool connectToDatabase(const std::string& connectionString) {
        try {
            // 尝试连接数据库
            if (connectionString.empty()) {
                HG_THROW_ERROR(ErrorCategory::DATABASE_CONNECTION_FAILED, 
                              "Database connection string is empty");
            }
            
            // 实际连接逻辑...
            return true;
            
        } catch (const HGException& ex) {
            // 异常已被基类自动处理，可以添加额外处理逻辑
            return false;
        }
    }
    
    ErrorInfo executeQuery(const std::string& query) {
        ErrorInfo result;
        
        if (query.empty()) {
            HG_SET_ERROR(result, 
                        ErrorCategory::DATABASE_QUERY_FAILED, 
                        ErrorSeverity::ERROR, 
                        "Query string is empty");
        }
        
        // 执行查询逻辑...
        
        return result;
    }
};
```

### 错误追踪配置

```cpp
#include "HGErrorTracker.h"

void setupErrorTracking() {
    // 设置最大追踪错误数量
    setMaxTrackedErrors(500);
    
    // 设置错误回调
    setErrorTrackingCallback([](const HGException& ex) {
        // 自定义错误处理逻辑
        if (ex.severity() == ErrorSeverity::CRITICAL) {
            // 发送警报通知
            sendAlert(ex.errorId(), ex.message());
        }
    });
    
    // 启用自动追踪
    enableAutoTracking(true);
}
```

## 总结

统一错误处理机制为vsproject系统提供了一致、可追踪和可维护的错误处理方法。通过遵循本规范，开发团队可以：

1. 提高代码质量和可维护性
2. 简化错误处理逻辑
3. 增强系统稳定性
4. 改善问题定位和调试效率
5. 提供更好的用户体验

所有新模块和功能都应遵循本规范，以确保整个系统的一致性和可靠性。
