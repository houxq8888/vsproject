# 依赖检查CMake模块使用说明

## 概述

本依赖检查CMake模块用于确保项目中的模块依赖关系符合依赖层次设计，防止循环依赖和不合理的跨层依赖。

## 文件说明

1. `cmake/dependency_check.cmake` - 核心依赖检查模块
2. `cmake/example_usage.cmake` - 使用示例
3. `tools/cmake_dependency_validator.py` - Python辅助验证脚本

## 功能特性

- **循环依赖检查**：检测直接和间接的循环依赖
- **跨层依赖检查**：确保模块不依赖上层的模块
- **同层依赖检查**：提示同层模块间的依赖（应尽量减少）
- **依赖关系图生成**：生成DOT格式的依赖关系图
- **层次属性设置**：为模块设置层次属性

## 使用方法

### 1. 在主CMakeLists.txt中引入依赖检查

```cmake
# 在主CMakeLists.txt文件开头添加
include(cmake/dependency_check.cmake)

# 按层次顺序添加子目录
add_subdirectory(services/HGAtomService/HGCommon)
add_subdirectory(services/HGAtomService/HGConfig)
add_subdirectory(services/HGAtomService/HGLogService)
# ... 其他模块

# 设置模块层次
setup_module_layers()

# 验证所有模块的依赖关系
validate_all_dependencies()

# 生成依赖关系图
generate_dependency_graph(${CMAKE_BINARY_DIR}/dependency_graph.dot)
```

### 2. 在模块CMakeLists.txt中添加检查

```cmake
# 在模块的CMakeLists.txt文件中
add_library(MyModule
    src/source1.cpp
    src/source2.cpp
)

# 设置模块层次
set_target_layer(MyModule 3)  # 第3层 - 业务服务层

# 添加依赖
target_link_libraries(MyModule
    HGCommon
    HGLogService
    HGSaveService
)

# 检查依赖关系
check_module_dependencies(MyModule 3)
```

### 3. 使用Python辅助验证脚本

```bash
# 运行验证脚本
python3 tools/cmake_dependency_validator.py --project-root . --output-json validation.json

# 生成依赖检查CMake代码
python3 tools/cmake_dependency_validator.py --project-root . --output-cmake my_checks.cmake
```

```

```

## CMake函数说明

### check_circular_dependencies(target)
检查指定目标是否存在循环依赖。

**参数：**
- `target` - 要检查的目标名称

**示例：**
```cmake
check_circular_dependencies(MyModule)
```

### check_layer_dependencies(target, layer)
检查指定目标是否存在跨层依赖。

**参数：**
- `target` - 要检查的目标名称
- `layer` - 目标所在的层次

**示例：**
```cmake
check_layer_dependencies(MyModule 3)
```

### check_same_layer_dependencies(target, layer)
检查指定目标的同层依赖。

**参数：**
- `target` - 要检查的目标名称
- `layer` - 目标所在的层次

**示例：**
```cmake
check_same_layer_dependencies(MyModule 3)
```

### check_module_dependencies(target, layer)
综合检查指定目标的依赖关系。

**参数：**
- `target` - 要检查的目标名称
- `layer` - 目标所在的层次

**示例：**
```cmake
check_module_dependencies(MyModule 3)
```

### generate_dependency_graph(output_file)
生成依赖关系图。

**参数：**
- `output_file` - 输出文件路径

**示例：**
```cmake
generate_dependency_graph(${CMAKE_BINARY_DIR}/dependency_graph.dot)
```

### set_target_layer(target, layer)
设置目标的层次属性。

**参数：**
- `target` - 目标名称
- `layer` - 层次编号

**示例：**
```cmake
set_target_layer(MyModule 3)
```

### setup_module_layers()
批量设置所有预定义模块的层次属性。

**示例：**
```cmake
setup_module_layers()
```

### validate_all_dependencies()
验证所有模块的依赖关系。

**示例：**
```cmake
validate_all_dependencies()
```

## 集成到构建流程

### 1. 修改build.sh脚本

在`build.sh`脚本中添加依赖检查步骤：

```bash
check_dependencies() {
    echo "Checking module dependencies..."
    python3 tools/cmake_dependency_validator.py --project-root . --output-json build/validation.json
    if [ $? -ne 0 ]; then
        echo "Dependency check failed!"
        exit 1
    fi
}

# 在配置阶段之前调用
check_dependencies
config $1
```

### 2. 集成到CI/CD

如果项目使用CI/CD，可以在构建流程中添加依赖检查：

```yaml
# .gitlab-ci.yml 示例
stages:
  - validate
  - build

dependency_check:
  stage: validate
  script:
    - python3 tools/cmake_dependency_validator.py --project-root . --output-json validation.json
  artifacts:
    reports:
      junit: validation.json
```

## 依赖关系图可视化

```bash

# 转换为SVG图片
dot -Tsvg dependency_graph.dot -o dependency_graph.svg
```

## 常见问题

### 1. 如何处理不可避免的跨层依赖？

如果确实需要跨层依赖，应该通过接口层进行：

```cmake
# 错误：直接跨层依赖
target_link_libraries(HighLevelModule LowLevelModule)

# 正确：通过接口层
target_link_libraries(HighLevelModule LowLevelInterface)
target_link_libraries(LowLevelInterface LowLevelModule)
```

### 2. 如何处理第三方库依赖？

第三方库依赖不会被检查，因为它们不在预定义的模块列表中。如果需要检查第三方库依赖，可以修改`dependency_check.cmake`中的`LAYER_MAPPING`变量。

### 3. 如何处理条件编译依赖？

条件编译依赖可能会导致误报，可以在CMakeLists.txt中使用条件语句来处理：

```cmake
if(SOME_CONDITION)
    target_link_libraries(MyModule ConditionalModule)
    check_module_dependencies(MyModule 3)
endif()
```

## 最佳实践

1. **定期检查**：在每次提交前运行依赖检查
2. **自动化集成**：将依赖检查集成到CI/CD流程
3. **及时修复**：发现依赖问题时及时修复
4. **文档更新**：添加新模块时更新依赖层次文档
5. **代码审查**：在代码审查中关注依赖关系

通过遵循这些最佳实践，可以确保项目的依赖关系始终保持清晰和合理。
